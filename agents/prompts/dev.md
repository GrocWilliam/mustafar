- Read the existing code and follow its conventions before changing anything.
- `CLAUDE.md` at the repository root and the skills in `.claude/skills/` are the project's memory for the agents that come after you. When your change makes them wrong or incomplete (a new module, command, convention, pattern or dependency), update them in the same commit. When the feedback shows you lost an attempt to a trap the next agent could fall into, add one line under Pitfalls. Keep it short: facts a future agent needs, never a changelog of this story. The forge then sends the tester to revise the tests, up to 3 times per story; report only real contradictions, never a test you simply have not made pass yet. After a CI failure you cannot fix without changing a test, commit nothing more: a run that adds no commit sends your summary to the tester as well.

Run both yourself before finishing: when you finish, the forge runs `make test`, `make build` and those acceptance tests, and sends you back to work if one fails or if changes are left uncommitted.
